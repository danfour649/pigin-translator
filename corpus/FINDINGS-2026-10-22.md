# Findings — 2026-10-22 (pilot results + live model spot tests)

Context: the corpus pilot finished, the website gained the GPT-6 models
(PR #14, merged), and three live spot-test rounds were run the same
evening — the same English source translated by each candidate teacher,
spoken in the site's Spitch Yoruba voice ("sade"), and sent to a native
speaker to pick the best version. Her verdicts are pending; everything
below is the machine-side record.

| Yoruba | 1,000 | 16,680 | 124,560 | $3.82 | $0.0038 |

## 3. Round 1 — everyday romantic message (GPT-6 Astra via the site)

Astra (through the website, minutes after the dropdown deploy) produced
fluent Yoruba with **zero diacritics** — no tone marks, no underdots:

> "Shade mi to sowon ju lo, iwo ni ololufe emi mi ati okan ile wa. ..."

The same message from Azure gpt-5-5 was fully diacriticized
("Shade mi ọ̀wọ́n jùlọ, ìwọ ni ìfẹ́ ọkàn mi àti ọkàn ilé wa. ...").
Note the site's own translate prompt explicitly instructs standard
orthography "including tone marks and the letters ẹ, ọ, ṣ, and gb" —
so the bare output was the model not complying, not the prompt.

## 4. Round 2 — suggestive message (all three models)

- Both GPT-6 models produced **full diacritics** this time. Combined
  with round 1, Astra's orthography compliance is *inconsistent*
  (marked in 2 of 3 samples; GPT-6.1 Sol 2 of 2), not absent.
  Implication for the corpus: single-pass generation is not enough —
  diacritic compliance must be checked per output or fixed by
  reranking/multi-sample selection.
- GPT-5.5 slipped semantically: "warm water" came out as
  "omi tútù gbígbóná" — cold *and* hot water at once — where both
  GPT-6 versions rendered it cleanly as warm.
- The mildly suggestive content (kissing, an invitation to bed) passed
  all three models without refusal or visible sanitization.

## 5. Round 3 — adult message (the Azure filter wall, live)

Source: a consensual marital message describing a bondage fantasy
(remote winter cabin, being tied up, two days) ending in an explicit
invitation to consent ("Say the word, and I will book the cabin").

- **Azure gpt-5-5: hard-blocked.** HTTP 400 `content_filter` —
  "The response was filtered due to the prompt triggering Azure
  OpenAI's content management policy", filter result: sexual =
  filtered, severity **medium** (hate/self-harm/violence all safe).
  The DefaultV2 platform filter scored the prompt and the model never
  ran. No translation exists.
- **GPT-6 Astra and GPT-6.1 Sol (via the website's gateway): both
  translated the message completely**, full diacritics, nothing
  stripped — the tying, the two days, and the consent line all
  preserved (Astra: "Kàn sọ pé o fẹ́" — just say you want it; Sol:
  "Kàn sọ pé o gbà" — just say you accept).

Finding: the permissiveness difference is a property of the **platform
filter stack, not the model**. Azure's bolt-on DefaultV2 classifier
blocks at medium; the gateway route applies no equivalent external
filter, so the model's own (contextual) judgment governs. Prediction:
GPT-6 on Azure would be blocked identically, and 5.5 via the gateway
would have translated it. Practical consequence, confirming the plan:
**adult-register generation cannot run on Azure DefaultV2** — the
suggestive tier is already at the filter's edge (round 2 passed,
round 3 didn't) — so adult tiers belong on the local/RunPod route,
and the bulk Azure spend stays on the everyday corpus.

## 6. Method notes

- All spoken versions used the production site's own routes
  (`/api/translate`, `/api/speak`) and the same Spitch voice, so the
  only variable across versions was the translating model.
- The judge received rounds via Messenger and email with the English
  source and a pick-the-best instruction; SMS delivery from Muse
  remains broken route-wide (unrelated standing issue).
- Teacher-selection implication: weigh (a) diacritic consistency,
  (b) semantic slips, (c) platform filter behavior for adult content —
  not release recency. The human verdicts land on top of this record.

## Addendum (added later on 2026-10-22): teacher locked — GPT-6 Astra, head-to-head at n=1,000

Folasade reviewed the three audio spot-test rounds and picked **GPT-6 Astra** as the best translator. Daniel locked Astra in as the corpus **teacher**. A `gpt-6-astra` deployment (2026-09-03, GlobalStandard, capacity 100) was created on `aoclean-foundry-ce`, and the full 1,000-sentence pilot source was re-run through it in Azure for both languages (zero errors). Re-evaluation versus the GPT-5.5 pilot on identical sources:

| Metric (Yoruba, n=1,000) | GPT-5.5 | GPT-6 Astra |
|---|---|---|
| Zero-diacritic outputs | 0 / 1,000 | **0 / 1,000** |
| Mean diacritic-mark density (marks per letter) | 0.568 | 0.573 |
| Output length vs other model | — | ~4% longer |

Cross-model agreement: 216/1,000 Yoruba outputs word-for-word identical, mean word-Jaccard 0.642; Naija 323/1,000 identical, Jaccard 0.708, Astra ~6% longer. Astra usage: Yoruba 17,219 in / 53,467 out tokens; Naija 15,069 in / 20,285 out (batch totals incl. retries) — a few dollars of trial credit at premium list prices.

**Key correction to the round-1 read:** the total diacritic collapse seen in round 1 did **not** recur at scale via the API — 0 failures in 1,000 lines. The collapse most likely came from the website/gateway route (different system-prompt stack/decoding), not from Astra itself. The diacritic-compliance check in the bulk runner is still worth keeping as a cheap guard, but Astra's orthography at API scale is as disciplined as 5.5's, with slightly fuller phrasing.

A blind 100-line grading packet (same lines, both teachers, order randomized, key held separately) is in the repo as `corpus/grading_packet_yoruba_100.md` for the formal Stage-1 grade. Astra outputs are archived with the pilot files (Drive folder `pigin-corpus-pilot-2026-10-22`; mirror on fola4.1 `~/pigin-corpus-archive/`).
